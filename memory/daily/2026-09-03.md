## 09:00 -- Lesson 1: Fail-open checks (three routes across four review rounds)

An optional verification skipped (treated as pass/not-applicable) when its input is missing, rather than failing closed. Phase 3's jq-free POSIX-sh route parser had 5 fail-open shapes across 4 rounds; a decoy rollout record could report `match`. Fixed only by switching to real `json.loads` + top-level-only dict access in Python. Phase 4's `integrity_ok` model had the runner defaulting the field to pass when a check could not run. Phase 4 hardening (`--` injection block) had no test for slot-1/2 case, so a refactor could silently reintroduce the fail-open. Rule: every mandatory check's ABSENCE must be explicit failure; regression test must assert the FAILURE mode (delete-the-line: removing the check reddens >=1 test).

## 09:00 -- Lesson 2: Trust-root path handed to the process it hides from (four instances)

Phase 4 runner disclosed operator origin path in four ways: withdrawn fingerprint design inside arm's git worktree; `SEFI_ARM_SESSION_FILE=<results-dir>/...` into arm's env; `git clone` left `file:///D:/.../<branch>` in `.git/config`; same path in `.git/logs/HEAD` reflog. Rule: scan the WHOLE containing structure (every file under `.git/`, not one named file). Clean fixes: arm scratch in private `mkdtemp` never disclosed to process; clone with `-c core.logallrefupdates=false` + `checkout --detach` + `remote remove origin`.

## 09:00 -- Lesson 3: git checkout on uncommitted working-tree destroys changes

`git checkout -- <path>` on a never-staged file silently restores it from the index (equals HEAD), destroying all changes. A fix agent wiped a 95-line security-reviewed shim this way and had to reconstruct it from conversation context. Rule: to set a file aside and restore it, use `cp` to scratch copy; never `git checkout` on a file whose changes are not committed.

## 09:00 -- Lesson 4: Re-golden discipline on fingerprinted inputs

Editing a fingerprinted input (benchmark prompt feeding `case_fingerprint = sha256(cat <prompt> <acceptance_check>)`) requires: recompute the hash by documented recipe, update EVERY pin, and run repo-wide grep for OLD hash to prove no cascade. Done correctly for 3 cases this run (e8cdb70f.., 81629762.., 3367dd21..). This is now a repeatable lesson for future case edits.

## 09:00 -- Lesson 5: Pipe exit code capture

`$?` captured after a pipe (`cmd | tail`) is the exit code of the LAST pipe segment, not `cmd`. Re-run without the pipe, or use `${PIPESTATUS[0]}` / `set -o pipefail`. Cost several wasted verification cycles this run.

## 09:00 -- Policy: Python in plugin scripts (one-time human authorization)

Human lifted "no Python in plugin scripts" for exactly two contributor-tooling scripts this run -- `plugins/sefi-core/scripts/check-route.py` (Phase 3) and `benchmarks/runner/` + `benchmarks/scorecard.py` (Phase 4) -- on the precedent that the repo already ships stdlib-Python contributor tooling. Not a general relaxation. This exception required explicit authorization; future requests require same human review.
