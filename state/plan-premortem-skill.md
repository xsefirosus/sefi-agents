## Objective
Adopt the externally-authored "premortem" skill (source: `C:\Users\Mary Rose\.claude\uploads\178f0085-b91b-42bc-a40a-1aa777140b58\7d6d680b-premortem_SKILL.md`, an 87-line, 5-stage forensic pre-execution failure analysis) into the sefi-agents plugin as (a) a new standalone on-demand skill at `plugins/sefi-core/skills/premortem/SKILL.md`, and (b) an optional, narrowly-triggered step wired into `product-manager.md`'s and `solutions-architect.md`'s own protocols -- never forced on a trivial goal, never returning its full inline output from inside a dispatched agent's own reply.

## Approach (two named alternatives, one chosen)
**Approach A -- inline duplication (rejected):** paste the ~87-line methodology directly into both `product-manager.md` and `solutions-architect.md` as inline optional protocol text, no separate skill file. Pro: zero indirection, no second file to load at runtime. Con: this repo's own last-known Proof snapshot (`README.md`'s Proof block) states the 13 agent files already total 8316 words against a `13 x 640 = 8320`-word aggregate cap (`validate-token-budget.sh`) -- roughly 4 words of headroom, total, across all 13 files. Duplicating an 87-line methodology into two agent files blows both that aggregate cap and each file's individual 150-line cap outright, and creates three copies of the same logic to keep in sync (the antipattern this repo's own `plugins/sefi-core/README.md` "Design rules" section explicitly rejects: "Single writer per artifact set").

**Approach B -- standalone skill + thin pointer wiring (chosen):** create ONE canonical skill body at `plugins/sefi-core/skills/premortem/SKILL.md` (the pattern already used for `security-review` backing `security-engineer` and `n8n-workflow-design` backing `solutions-architect`), and wire the two agents with a short (~30-40 word) optional-trigger pointer step each that names the skill, states the concrete trigger condition, and states the file+digest output rule -- never restating the methodology. Pro: matches this repo's own established Signature/Craft/Gate skill pattern, stays inside the tight aggregate word budget, single edit point if the methodology changes later. Con: a reader following the wired agent's protocol has to open a second file (`skills/premortem/SKILL.md`) to see the full methodology, same one-hop indirection every other Craft/Gate skill already requires.
